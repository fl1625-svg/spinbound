# SPINBOUND 3.0 Unity True-3D Vertical Slice Design

## Status
Approved architecture: complete restart from Phaser 2.x to Unity 6.3 LTS + URP true 3D. Old code/art/UI/audio are not production dependencies.

## Product goal
Build one production-quality W1-1 vertical slice for CrazyGames that uses AAA production discipline at web scale: true 3D environment, stylized PBR materials, authored lighting, polished camera, VFX, audio, UI, rigorous performance tiers, deterministic precision gameplay, and professional release QA.

## Engine and platform
- Unity 6.3 LTS; project baseline targets 6000.3.18f1 or newer 6000.3 LTS patch.
- Universal Render Pipeline (URP 17 family), Forward rendering for broad WebGL compatibility.
- WebGL 2 / WebAssembly target for CrazyGames.
- CrazyGames Unity SDK v3 integration behind a platform boundary; custom CrazyGames release build is the target packaging path.
- Brotli-compressed release builds.

## AAA-at-web-scale interpretation
"AAA" is a quality/process bar, not console-sized content volume. One vertical slice must have coherent art direction, production 3D assets, PBR/stylized materials, lighting, animation, VFX, camera, audio, UI, accessibility-conscious controls, profiling, memory/build budgets, automated regression gates and release QA.

## Gameplay truth
- Gameplay plane is XZ; Y is presentation/elevation only for the rotor path.
- Authoritative gameplay runs at fixed 120 Hz.
- Rotor angular speed is fixed 60 deg/s clockwise; player input never changes angular speed or direction.
- Normal half-length 1.44 m, capsule radius 0.16 m.
- Assist half-length 1.08 m; same course geometry; noncompetitive result flag.
- Movement tiers: Precision 2.2 m/s, Fast 3.3 m/s, Turbo 4.4 m/s.
- Desktop: Shift=A, Space=B, either Fast, both Turbo. WASD/arrows move.
- Mobile: floating stick + A/B speed buttons.
- Precision collision is custom deterministic capsule-vs-course geometry on XZ; Unity PhysX is not authoritative for rotor-course contacts.

## W1-1 vertical slice
Theme working name: Daisy Highlands. It is an original sunlit highland garden route with stone/earth paths, timber structures, wind-reactive vegetation, distant terrain, authored vista beats, and no Nintendo characters, props, level geometry, UI, melodies, or sound-alikes.

The slice must contain:
- loading/bootstrap scene,
- front-end/menu,
- one full W1-1 course,
- checkpoints and Heart Garden,
- normal + Assist clear,
- fail/restart/pause/result flow,
- desktop + touch controls,
- camera presentation and finish sequence,
- production HUD/result UI,
- dynamic music layers, SFX and ambience,
- High/Medium/Low quality tiers,
- CrazyGames lifecycle boundary,
- WebGL release build profile.

## Rendering direction
- True 3D meshes, not sprite-based faux geometry.
- Stylized PBR: sculpted forms, bevel discipline, authored roughness/normal/AO, coherent texel density.
- One dominant directional light plus baked/static lighting where useful, probes for moving hero object, reflection probes where affordable.
- Soft shadows and contact grounding; no expensive desktop-only HDRP features.
- Subtle post: color grading, bloom only for emissive hero beats, restrained vignette/contrast; gameplay readability always wins.
- Vegetation animation is vertex/shader or GPU-friendly, with quality-tier density scaling.

## Camera
- Fixed oblique adventure camera, stable enough for precision control.
- Directional look-ahead and mild speed-dependent FOV/distance changes only.
- No camera rotation during active precision traversal.
- Short finish cinematic after authoritative completion.

## Art production rules
- Greybox is allowed as an engineering stage but may never be presented as final art.
- Final visible assets must be production 3D assets or deliberately authored VFX/UI; no primitive-cube final scenery.
- Asset provenance must be recorded.
- Environment collision geometry is authored separately from render meshes.

## Audio
- Original music only, with stems/layers for exploration and finale intensity.
- Dedicated ambience and one-shot SFX mix groups.
- Audio Mixer buses: Master, Music, SFX, Ambience, UI.
- No recognizable Nintendo motifs or sound-alikes.

## Performance targets
- Desktop High target: 60 FPS at 1080p on a representative midrange discrete GPU browser.
- Mobile Medium target: 60 FPS where viable; 30 FPS is the minimum supported floor on weaker devices without changing gameplay truth.
- Authoritative simulation remains 120 Hz even when render rate is 30/60 Hz.
- First-interactive payload target is aggressively minimized; large environment/audio assets stream after bootstrap.
- Release uses CrazyGames custom build analysis and device-appropriate texture variants when available.

## Hard gates
1. Core simulation unit tests pass before scene work.
2. Collision/render separation tests pass before art integration.
3. W1-1 deterministic reference route passes Normal and Assist without contact.
4. Browser quality/performance gate must pass before a second course is authored.
5. User must approve W1-1 visual, audio, movement, camera, UI and mobile quality before W1-2 begins.
