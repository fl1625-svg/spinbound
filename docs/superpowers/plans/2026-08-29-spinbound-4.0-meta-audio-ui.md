# SPINBOUND 4.0 Meta, Audio & UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add replay-driving progression, 3D diorama world-map flow, Orbit Cores/mastery, fast results/retry, production audio architecture, minimal HUD/settings, and accessibility without obscuring the precision game.

**Architecture:** Meta state is separate from authoritative per-run simulation. Run results are immutable records consumed by progression, world map, ghost and UI systems. Audio reacts to read-only gameplay events through a mixer/stem director. UI is presentation-only and cannot decide physics.

**Tech Stack:** Pure C# meta data, Unity UGUI, Unity AudioMixer/AudioSource, serialized local save data, PlayMode tests.

**Spec:** `docs/superpowers/specs/2026-08-29-spinbound-4.0-design.md`

## Global Constraints

- Up to three Orbit Cores per ordinary stage; they reinforce route/skill/mastery, not arbitrary corner placement.
- Completion states: CLEAR, PERFECT, MASTER TIME, CROWN mastery package.
- Main progression is not aggressively gated by collectibles.
- World selection is a playable 3D diorama map, not a flat level list.
- Default HUD: hearts, timer, collectible state, very small speed indicator only if useful.
- Production audio has music, gameplay SFX, ambience, UI, stingers; prototype audio cannot ship.
- Separate music/SFX/ambience/UI volume controls are required.
