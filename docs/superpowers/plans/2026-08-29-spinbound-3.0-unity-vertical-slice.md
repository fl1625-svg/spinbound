# SPINBOUND 3.0 Unity True-3D Vertical Slice Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a clean Unity 6.3 LTS/URP foundation and one true-3D W1-1 vertical slice for CrazyGames with deterministic precision gameplay and AAA production discipline at web scale.

**Architecture:** Unity owns true-3D rendering, scene composition, camera, UI and audio. A small deterministic gameplay core owns the 120 Hz XZ-plane rotor simulation and custom capsule collision so visual meshes and PhysX cannot change precision gameplay truth. Platform calls are isolated behind an interface so Editor/testing never depends on the CrazyGames SDK package.

**Tech Stack:** Unity 6.3 LTS (6000.3.x), C#/.NET Standard profile, URP 17, Unity Input System, Cinemachine, Unity Test Framework, WebGL 2/WebAssembly, CrazyGames Unity SDK v3, Brotli/custom CrazyGames build.

**Spec:** `docs/superpowers/specs/2026-08-29-spinbound-3.0-unity-vertical-slice-design.md`

## Global Constraints
- Fixed authoritative simulation: 120 Hz.
- Fixed rotor angular speed: 60 deg/s clockwise; input cannot alter rotation.
- Normal rotor half-length 1.44 m; Assist 1.08 m; radius 0.16 m.
- Center speeds: 2.2 / 3.3 / 4.4 m/s.
- Authoritative collision is custom XZ capsule collision; render meshes and PhysX are non-authoritative.
- True 3D URP production presentation; no sprite/faux-3D production fallback.
- No Nintendo characters, props, UI, map geometry, music motifs, or recognizable IP-specific iconography.
- Do not author W1-2 until W1-1 has passed automated/browser/mobile quality gates and explicit user approval.
