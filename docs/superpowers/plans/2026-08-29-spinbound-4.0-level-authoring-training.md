# SPINBOUND 4.0 Level Authoring, Solver & Training Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a data-driven phase-aware stage authoring system, automated route verifier, five training stages, Practice section starts, and deterministic Demo/Ghost foundation before producing World 1 content.

**Architecture:** `Spinbound.Worlds` remains Unity-engine-free and defines immutable stage data; `Spinbound.Core` executes it; Editor tooling converts stage definitions into Unity presentation scenes. Reference routes are explicit input scripts first; solver analysis expands over starting phase and speed choices without becoming the runtime authority.

**Tech Stack:** Pure C# stage data, NUnit EditMode tests, Unity Editor builders, JSON/ScriptableObject export only at presentation boundary.

**Spec:** `docs/superpowers/specs/2026-08-29-spinbound-4.0-design.md`

## Global Constraints

- Every important obstacle segment records entry phase, allowed phase window, intended speed, center trajectory, exit phase, safe solution, and skilled/optimization solution where applicable.
- Every normal/training stage must have at least one no-damage authored reference route.
- Critical geometry cannot be authored from presentation meshes.
- Training 1–5 teach: movement/rotation; waiting/Straight Gate; speed tiers; L-bend endpoint awareness; S-bend + Heart.
- No text wall tutorials; geometry and staging teach the mechanic.
