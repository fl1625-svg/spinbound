# SPINBOUND 4.0 Web Release & QA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the approved World 1 vertical slice into a verified CrazyGames-ready Web build with correct lifecycle integration, loading/compression behavior, mobile input, performance tiers, and reproducible QA evidence.

**Architecture:** Preserve `IPlatformBridge`; keep platform calls outside Core. Build configuration is generated by Editor code so local and CI builds are reproducible. Quality selection changes only presentation budgets, never gameplay/camera geometry/input/hazard timing.

**Tech Stack:** Unity Web build, URP, CrazyGames bridge boundary, Brotli/static server compatibility, Python source/budget audits, browser/device manual QA.

**Spec:** `docs/superpowers/specs/2026-08-29-spinbound-4.0-design.md`

## Global Constraints

- Real Web build testing is mandatory; source checks cannot pass release/performance gates.
- Desktop High 60 FPS target; mobile Medium 50–60 FPS target; Low stable 30 FPS priority.
- High visible draw-call budget target <150–200; Medium <100–140; Low <80–100.
- Initial playable compressed payload target approximately 15–25 MB where practical.
- Quality tiers cannot change gameplay geometry, collision, camera geometry, rotor visibility requirements, hazard timing, or input behavior.
